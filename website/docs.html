This guide summarizes the checked-in SeaWorld DB documentation. Stable V1 and the current 1.1.0-beta pre-release are differentiated in the repository release notes.

Quickstart

Add the published stable package, then create a local database file from Rust. Use Database::open for a writable existing database and Database::open_reader for a fixed read-only view.

[dependencies]
seaworld-db = "1.0.0"

Storage model

SeaWorld is a document-native engine. Collections contain flexible documents with null, booleans, signed integers, finite floats, strings, bytes, arrays and nested objects. The limited SQL V0 layer lowers into the same native query and transaction engine; it is not full SQL compatibility.

Durability

A V2–V4 commit writes a complete transaction batch, calls File::sync_all, then publishes in-memory state. That establishes the documented process-crash boundary only; it is not a universal power-loss or filesystem guarantee.

WAL & recovery

SeaWorld stores a checksummed append-only record log. On writable open an incomplete final transaction tail is discarded from its begin record; read-only open reports recovery required instead. Complete checksum failures and invalid sequences fail closed.

Compaction, backup & restore

Backup writes a validated compacted V4 copy. Restore validates its source and writes a new target. These flows do not overwrite existing targets; V1 exposes no compact CLI command.

Public API

The V1 public boundary exposes owned values and typed errors, not pages, cursors, log records, planner internals or B+Tree handles. API 1.0.0 remains the stable contract throughout API major version 1.

Rust & Java compatibility

Rust is the supported V1 integration surface. The checked-in Java-generated V1 fixture is a compatibility fixture—not a documented Java client or server compatibility promise.

Compatibility contract ↗

Testing & security

The repository documents semantic process-crash, generated, differential and index/full-scan testing. The V1-qualified platforms are Ubuntu 24.04 x86_64 and Windows latest x86_64; ARM64/Raspberry Pi is not V1-qualified.
